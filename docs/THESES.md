# Theses for the diploma

Short scientific paper (2–3 pages) on a topic related to the diploma. The format requirements of the university are still to be provided.

## Topic

Comparison of approaches to delivering vector tiles for a web map with open geodata, using the settlements of Germany as an example.

## Problem

Flanr shows its own data layer on the map: points and boundaries of settlements, tens of thousands of polygons for Germany alone. Sending all of it to the client as one GeoJSON is too heavy. Vector tiles are the standard solution, but they can be produced in different ways with different trade-offs in speed, cost and data freshness.

## Approaches compared

1. Full GeoJSON as a baseline.
2. Dynamic tiles generated by PostGIS (`ST_AsMVT`) on request, through a Hono endpoint or the Martin tile server.
3. Pre-generated PMTiles (built with tippecanoe), a static file read by the client through HTTP range requests, can be served from a CDN.

## Metrics

- Tile response time (median and p95) at different zoom levels.
- Time to first map render in the browser.
- Amount of data transferred.
- Storage size and generation time.
- Freshness: how quickly data changes appear on the map.
- Infrastructure complexity and hosting cost.

## Hypothesis

For static geometry, which changes only with the monthly import, PMTiles are faster and cheaper. Dynamic tiles are only needed where data depends on the user, such as colouring cities by the user's rating. The best approach for Flanr is therefore a hybrid: geometry from PMTiles, user data from the API, applied on the map through feature-state.

## Structure

1. Relevance: open geodata and the cost of commercial map APIs.
2. Goal and tasks.
3. Method: data, test setup, metrics.
4. Results: one table and one chart.
5. Conclusions: recommended approach.
6. References: 5–8 sources (Mapbox Vector Tile specification, PMTiles, PostGIS documentation, papers on tiling).
